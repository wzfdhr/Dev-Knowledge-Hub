# Dev Knowledge Hub 中文优先设计

## 目标

Dev Knowledge Hub 的管理台与知识生成结果默认使用简体中文，降低中文开发团队的使用成本。代码标识、文件路径、协议名和可验证引用保持原样，确保知识内容仍能直接对应源码。

## 范围

- 中文化首次设置、登录、总览、知识、反馈、设置及移动端导航中的用户可见文案。
- 中文化加载、空状态、错误、成功、确认、筛选、分页、工具提示和无障碍标签。
- 中文化确定性知识生成模板，包括架构概览、模块职责、开发约定、运行指南、测试指南和符号说明。
- AI 增强提示明确要求输出简体中文，同时不得翻译代码标识、路径、命令、Commit SHA、Blob Hash 或引用字段。
- API、数据库、MCP 工具名和内部状态枚举保持英文，前端通过集中映射显示中文。

## 术语规则

- 保留 `MCP`、`API`、`Token`、`Commit`、`Blob`、`Git`、`HTTPS`、`OpenAI`、`Anthropic` 等行业术语。
- 保留函数名、类名、模块名、文件路径、命令和配置键。
- 构建状态、反馈状态和仓库类型仅在展示层翻译，传输值不变。
- 产品名 `Dev Knowledge Hub` 保持英文，副标题和操作说明使用中文。

## 实现边界

前端继续沿用现有 React 组件结构，不引入完整 i18n 运行时。通用状态标签和共享 UI 文案集中到轻量的中文映射或辅助函数，页面专属文案保留在对应页面。知识生成器以中文确定性模板为基线，模型增强器追加中文输出约束。此次不增加语言切换器，也不迁移历史发布内容；新构建生成中文知识，旧发布继续按原内容读取。

## 错误与兼容性

服务端稳定错误码保持不变。已由后端返回的底层错误详情不强制机器翻译，前端框架性说明和操作按钮使用中文。所有 API 参数、响应结构、MCP envelope 和数据库迁移保持兼容。

## 测试与验收

- 先更新或新增组件测试，使中文导航、关键操作、状态映射和无障碍名称成为失败断言，再修改实现。
- 生成器测试断言核心知识页标题和正文为中文，并验证引用、路径、符号名未被翻译。
- Playwright 覆盖中文首次设置、构建、知识查看、发布、Token 和反馈流程。
- 运行单元测试、类型检查、Lint、生产构建和 Playwright。
- 在桌面及移动视口检查中文文案不溢出、不遮挡，并刷新本地预览供确认。

## 非目标

- 本轮不提供中英语言切换。
- 不翻译源码内容或第三方模型、仓库返回的专有名称。
- 不重写已经发布的旧知识快照。
- 不改变认证、构建、检索、发布或 MCP 的业务行为。
