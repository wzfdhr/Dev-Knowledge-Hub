# 可滚动工作区与质量引导设计

## 目标

让桌面端的长列表和长详情在各自工作区中滚动，而不是撑高整页；让知识质量页面直接说明用户当前该做的事。

## 适用范围

- 知识资料：目录、正文和来源代码面板。
- 反馈：反馈列表和反馈详情。
- 图谱：画布旁的节点/关系详情及来源代码面板。
- 知识质量：问题列表、问题详情、代码元数据列表。

## 桌面布局规则

在宽度大于 760px 时，以上双栏或三栏工作区拥有可视区高度上限。每个可增长的列都设置 `min-height: 0`，并由该列自身处理纵向滚动：列表使用稳定滚动槽，详情与来源在内容很长时独立滚动。工作区不再因任一列的内容而无限变高。

知识资料的“页面”标题保留在左栏顶部，仅页面条目区域滚动。来源抽屉、图谱画布自身已有的横向滚动不改变；长路径继续在可用宽度内换行或截断，不能触发页面级横向溢出。

在 760px 及以下，保留现有移动端自然页面流和来源底部抽屉：不强制固定高度，目录维持现有横向/短列表行为，避免嵌套滚动损害触摸体验。

## 质量引导

质量治理顶部新增当前待办说明。默认聚焦还需要人工推进的状态：

1. `open`：选择问题，接受处理或填写理由忽略。
2. `accepted`：说明已确认范围，下一步是请求范围重建。
3. `rebuilding`：说明候选仍在生成；只有候选完成并审核后，才可标记已解决。
4. `resolved` 与 `dismissed`：归入已完成/已忽略，不作为默认待办干扰当前处理。

选中问题后，详情页显示一条与当前状态一致的“下一步”说明，并把唯一推荐操作放在说明之后。现有权限、状态机、重建 API 和“不会自动发布”的安全语义保持不变。

## 可访问性与验收

- 滚动容器可键盘聚焦到内部控件，不产生页面级横向滚动。
- 状态和待办文案不只依赖颜色。
- 桌面 1440×1024 和 768×900 下，长列表可在所在栏滚动；390×844 保留可用的自然流/底部抽屉。
- 只读成员看得到待办和状态，但不显示生产操作。
