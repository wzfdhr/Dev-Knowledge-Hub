# 融合型项目工作台改版设计

日期：2026-07-13

## 目标

将当前由“项目中心 + 大而全设置页”组成的管理台，改造成以项目为中心的团队知识工作台。用户进入项目后，可在同一上下文内完成资料导入、知识构建与发布、团队协作和 Codex 接入。

设计同时满足两个管理视角：

- 开发总监可以快速判断版本、构建、发布、风险、负责人和 Agent 接入状态。
- 设计总监可以获得清晰的信息层级、一致的状态表达、合理的内容密度和稳定的响应式体验。

## 设计方向

采用已确认的“融合型项目工作台”：保留研发工具所需的信息密度，但通过顶部项目上下文、项目级导航、轻量分区、固定状态语义和一致间距建立视觉秩序。

视觉语言沿用现有 Ant Design 5 和 `af-ideal-admin` 的后台产品特征：

- 48 至 56 像素顶部工具栏，可折叠深色导航。
- 浅灰工作区与白色内容面，不使用大面积装饰或营销式首屏。
- 6 像素圆角、细分隔线、极少阴影，蓝色仅用于主要操作和当前状态。
- 正文 14 像素，页面标题 22 至 24 像素，紧凑表格和列表保持可扫描性。
- 状态不能只依赖颜色，同时显示图标、文本和阶段名称。

## 信息架构

### 全局导航

- 项目中心：团队全部项目及其当前发布、存储、成员和健康状态。
- 全局知识：跨项目检索已发布知识。
- 反馈中心：汇总 Agent 与成员反馈，并可按项目筛选。
- 团队空间：成员、角色、项目权限和全局活动。
- 系统设置：模型服务、安全、存储与备份。

### 项目工作台

进入项目后，顶部始终显示项目名称、内容版本、当前发布和成员数量。项目级导航固定为：

1. 项目概览
2. 资料上传
3. 知识版本
4. 团队协作
5. Codex 接入

旧 `/overview` 页面迁移为项目概览。旧设置页中的仓库连接和上传迁移到资料上传，MCP 连接和 Token 迁移到 Codex 接入。设置页不再承载项目业务。

## 页面设计

### 项目中心

项目列表使用可扫描表格而非装饰性卡片。每行展示项目名称、当前发布、知识覆盖度、成员、最近导入、存储占用和状态。主要操作是“打开项目”，次要操作收纳到菜单。

顶部提供团队级摘要：项目总数、正在构建、待处理反馈和本周更新。摘要只用于快速判断系统负载，不重复项目行信息。

### 项目概览

首屏展示三个核心事实：当前知识版本、知识覆盖率、本周协作活动。下方分为主区和侧区：

- 主区：当前上传或构建任务、最近知识变化、待发布版本。
- 侧区：项目成员、最近活动、待处理反馈。

没有进行中任务时，主区展示最近一次成功版本和“上传新版本”操作，不显示空进度条。

### 资料上传

资料上传为独立页面，首要入口为“选择项目文件夹”，ZIP 为兼容入口。上传流程固定为六阶段：

1. 读取文件
2. 安全过滤
3. 本地压缩
4. 分块上传
5. 服务端校验
6. 创建内容版本

进度区域展示：当前阶段、总进度、当前文件或分块、已上传/总大小、上传速度、预计剩余时间、暂停/继续和取消。浏览器刷新后使用现有续传会话恢复进度。

过滤完成后展示报告：扫描文件数、可采集文件数、忽略文件数、准备上传大小及各忽略原因。报告确认后才开始压缩和上传。

页面下方是导入历史表，包含文件名或目录名、提交人、内容版本、采集/忽略数量、状态、耗时和创建时间。

### 知识版本

整合现有构建和发布操作，采用版本时间线加构建详情抽屉。每个版本显示内容版本、构建状态、知识页数量、符号数量、变更范围、创建人和发布时间。

`ready` 状态允许管理员手动发布；失败版本不会影响当前发布。当前发布始终置顶并明确标记。

### 团队协作

项目成员列表展示头像、邮箱、项目角色、最近活动和加入时间。管理员可以邀请成员、调整项目角色或移除项目访问权。

活动流记录资料上传、构建、发布、知识确认、反馈状态变更和 Token 创建/撤销。每条活动包含操作者、动作、目标、时间和可访问的详情入口。

团队空间负责全局成员管理；项目工作台只管理当前项目成员和活动。两者职责不重叠。

### Codex 接入

集中展示连接状态、MCP 端点、项目级 Token、配置片段和 `AGENTS.md` 模板。Token 必须绑定用户和项目，只展示一次明文。

页面提供连接检查，分别验证端点可访问、Token 有效、项目已发布及 MCP 工具可调用。任何失败都给出明确修复动作。

### 系统设置

改为内容区左侧设置子导航，在窄屏折叠为下拉菜单，仅包含：

- 模型服务：服务商、模型、API Key 状态和连通性测试。
- 安全：管理员会话、主密钥状态、审计保留策略。
- 存储与备份：数据库、快照、上传暂存区占用及备份状态。

## 上传状态与数据流

浏览器扫描文件夹时复用共享过滤规则，生成过滤报告。用户确认后，浏览器仅将可采集文件压缩为临时 ZIP，并使用现有 8 MB 分块协议上传。

客户端维护聚合状态：

- `phase`：六个固定阶段之一。
- `processedFiles / totalFiles`：扫描和过滤进度。
- `processedBytes / totalBytes`：压缩和上传进度。
- `receivedChunks / chunkCount`：续传进度。
- `bytesPerSecond / estimatedSeconds`：速度和剩余时间。
- `status`：`idle / running / paused / failed / completed / cancelled`。

服务端继续执行 ZIP 路径安全、解压限制、文件过滤和内容哈希校验。客户端过滤用于隐私和体验，服务端过滤是最终安全边界。

上传成功后创建不可变快照，不自动构建或发布。项目概览显示“待构建”状态，引导成员进入知识版本页。

## 权限与协作规则

- 管理员：项目、成员、构建、发布、Token 和系统设置的全部权限。
- 成员：上传、发起构建、处理反馈和查看项目活动；不能发布或管理成员。
- 只读：查询已发布知识、查看来源和项目活动；不能上传或写入。

所有写操作必须在界面中显示操作者，并写入审计事件。角色不足时隐藏不可用的主要操作，同时服务端继续返回 403 作为最终权限边界。

## 异常与恢复

- 扫描失败：保留已统计结果，指出失败文件和原因，可重新扫描。
- 压缩失败：不创建上传会话，可重试压缩或重新选择目录。
- 网络中断：显示已完成分块和恢复入口，重连后继续上传。
- 服务端校验失败：明确区分无效 ZIP、路径风险、超限和内容错误，不创建快照。
- 构建失败：保留日志与旧发布，提供重试和返回当前发布入口。
- 无发布版本：Codex 接入页显示未就绪状态，不生成误导性的可用提示。

全局通知只用于跨页面完成或失败；当前页面的进度和错误必须就地显示。

## 响应式与可访问性

- 1200 像素以下使用抽屉导航，项目级标签允许横向滚动或折叠为菜单。
- 760 像素以下，指标改为单列，表格提供关键字段移动视图，进度阶段改为纵向步骤。
- 所有按钮、输入和步骤具有可读标签；上传进度使用 `aria-live` 提示关键阶段变化。
- 键盘可完成选择文件夹以外的所有流程；文件系统选择器使用浏览器原生交互。
- 文本和交互目标满足常见对比度及 44 像素触控目标要求。

## 组件与代码边界

拆分当前大型设置页，形成独立页面和组件：

- `ProjectLayout`：项目上下文与项目级导航。
- `ProjectOverviewPage`：项目状态和团队动态。
- `ProjectImportsPage`：文件夹/ZIP 导入与上传历史。
- `ProjectVersionsPage`：构建和发布版本。
- `ProjectCollaborationPage`：项目成员与活动。
- `ProjectCodexPage`：MCP 接入和 Token。
- `SystemSettingsPage`：全局系统设置。
- `UploadProgress`、`ImportReport`、`ProjectActivity`：可独立测试的领域组件。

上传状态计算放在 API/领域层，不写进页面组件。页面只负责触发操作和呈现状态。

## 测试与验收

- 单元测试覆盖上传阶段聚合、速度/剩余时间、暂停恢复、过滤报告和角色可见性。
- 组件测试覆盖项目导航、上传进度、错误恢复、团队活动和系统设置拆分。
- Playwright 覆盖创建项目、选择文件夹、确认过滤报告、断线续传、创建快照、构建发布、邀请成员和生成 Codex 接入配置。
- 视觉验收覆盖 1440、1024、760 和 390 像素宽度，重点检查导航、上传步骤、表格与抽屉无溢出。

验收标准：首次进入的用户在 30 秒内可以找到项目上传入口；上传期间能明确回答“现在进行到哪一步、还要多久、失败后怎么办”；项目负责人能在概览页看到当前版本、团队参与和待处理事项。

## 本轮范围

本轮实现页面结构、上传进度和团队协作可见性，并复用现有后端能力。暂停上传、精确速度估算、项目级成员关系和完整活动事件若后端尚无数据支持，先建立真实接口边界和可恢复状态，不使用虚假的静态业务数据。

GitHub 自动同步、OSS 大文件通道、计费、多租户组织和完整通知中心不在本轮范围。
