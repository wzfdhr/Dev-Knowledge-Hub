# 本地文件夹导入设计

## 目标

让用户选择本机项目文件夹后，由浏览器在本地扫描并按 Dev Knowledge Hub 的统一规则过滤内容；服务器只接收保留的源码、文本配置和文档。Codex 可调用同一导入服务处理用户明确提供的本地路径。

## 范围

- 移动端把固定侧栏改为顶部栏和抽屉导航，避免内容区被挤出视口。
- 新增“选择项目文件夹”导入入口，优先使用浏览器 File System Access API；不支持时回退为目录文件选择。
- 在上传前本地展示文件总数、采集数量、忽略数量、分类原因和预计上传大小。
- 保持 ZIP 导入作为兼容入口，但不再要求用户自己过滤或压缩目录。
- 目录导入使用现有可续传上传会话；服务端仍执行第二道过滤和安全校验。
- Codex 路径导入复用同一份过滤器和上传协议，不接受网页中直接输入任意本机绝对路径。

## 流程

1. 用户在当前项目的设置页点击文件夹图标并授权选择目录。
2. 浏览器递归扫描目录，排除 `.git`、`node_modules`、构建目录、密钥、二进制、生成文件和超过限制的文本。
3. 界面显示导入报告。用户确认后，浏览器将保留条目打包为标准 ZIP 流并按 8 MiB 分块上传。
4. 服务器重新校验 ZIP、建立不可变快照，并删除上传暂存内容。
5. 用户手动构建、审核并发布知识版本。

## 边界与安全

- 浏览器只读取用户选择的目录；线上服务无法访问用户电脑的绝对路径。
- 过滤逻辑在浏览器和服务端双重执行，服务端判断为最终准则。
- 原始 ZIP 与临时分块在导入处理完成后删除；长期只保留已过滤快照。
- 目录最多 50,000 个文件，筛选后的上传内容仍受 500 MiB 压缩包和 2 GiB 解压限制。
- 浏览器不支持目录选择时展示可用的目录文件回退方式，而非要求用户手动过滤。

## 验收

- 333px 宽度下可打开导航、切换页面且内容完整可见。
- 对一个含依赖、构建产物和 `.env` 的项目目录，报告准确列出忽略原因，上传后引用只指向保留文件。
- 中断后可恢复上传；完成后重新上传相同内容为无操作。
- ZIP 和目录导入的过滤结果一致。
