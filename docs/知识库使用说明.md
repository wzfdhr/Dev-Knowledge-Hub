# Dev Knowledge Hub 使用说明

> 更新时间：2026-08-06  
> 适用对象：项目管理员、项目成员、知识消费者与接入 Codex 的开发者

## 这是什么

Dev Knowledge Hub 用于把项目源码和文档沉淀为可追溯的团队知识。每一份知识都绑定资料快照和精确来源；只有经过审核并发布的版本会被项目成员、搜索和 MCP 使用。

它不是自动覆盖线上知识的工具：接入资料、构建、失败重试、草稿审核均不会改写当前已发布版本。发布始终需要人工确认。

## 使用路径

项目内只有五个一级入口：

| 入口 | 什么时候用 | 能完成什么 |
| --- | --- | --- |
| 项目概览 | 不确定下一步时 | 查看资料生命周期、唯一主任务、当前发布和待处理反馈 |
| 资料接入 | 首次建立资料来源或导入新资料时 | 上传本地项目文件夹、连接 Git HTTPS 或服务器本地路径 |
| 知识生产 | 资料已接入后 | 创建快照、发起构建、查看阶段进度、创建草稿、重试失败任务 |
| 知识资料 | 阅读、审核或消费知识时 | 浏览页面与正文、查看来源、处理质量问题、查看图谱和前端地图 |
| 项目设置 | 管理项目协作与智能体接入时 | 管理团队协作、生成或撤销项目 MCP Token、获取 Codex 配置 |

“知识资料”包含四个二级入口：**页面**、**质量**、**图谱**、**前端地图**。前端地图只向管理员显示。

全局“知识库”只负责跨项目搜索和最近查看，不承载项目发布、质量治理或版本操作。

## 从资料到正式知识

按下面的顺序完成一个版本：

1. 在“资料接入”连接来源或上传项目文件夹。
2. 创建不可变快照；资料接入成功只代表资料可用，正式知识尚未变化。
3. 在“知识生产”开始构建。构建过程和阶段状态会实时刷新。
4. 构建完成后创建草稿，进入“知识资料”检查正文、目录和来源。
5. 确认无误后发布版本。发布后，该版本才会成为项目的正式知识，并可被 MCP 读取。

项目概览会根据当前状态只突出一个下一步操作：

| 当前状态 | 建议操作 |
| --- | --- |
| 尚未接入资料 | 接入资料 |
| 已接入、尚无快照 | 创建快照 |
| 快照已就绪 | 开始构建 |
| 构建中 | 查看进度 |
| 构建完成 | 创建草稿并审核 |
| 草稿审核中 | 发布版本 |
| 已发布 | 查看知识资料 |
| 构建失败 | 查看原因并重试 |

## 资料接入

推荐直接选择原始项目文件夹。浏览器会在上传前排除依赖、构建产物、二进制和敏感文件，服务端会再次校验。也可使用 Git HTTPS 或服务器可访问的本地路径。

- 文件夹上传支持续传。中断后，已验证文件会保留约 24 小时；刷新后重新选择同一文件夹即可安全继续，不会自动发布或重复创建内容版本。
- 不支持 ZIP 导入。
- 依赖与构建目录不会作为知识来源；请上传项目原始目录，而不是 `node_modules`、`dist` 或打包后的压缩副本。
- 导入完成后，请跟随“知识生产”的主按钮继续，不需要到全局知识库查找下一步。

## 知识生产与 LLM 增强

“知识生产”展示当前资料、构建历史、阶段详情与版本操作。构建失败会保留失败阶段和原因，重试会新建 attempt，不覆盖历史证据，也不会影响已发布知识。

管理员或项目管理员可在发起构建时启用 LLM 增强。完成后查看构建详情中的状态：

- **LLM 增强成功**：本次生成已获得 LLM 补充说明。
- **LLM 未生效，已使用基础生成**：构建仍然完成，但增强服务不可用或未通过校验；可查看 warning 了解原因。
- **未启用**：本次使用确定性的基础生成。

前端图谱或前端地图依赖前端候选包。若页面提示“候选包仍在生成”，等待本次构建完成；若提示候选包无效，打开构建详情查看失败阶段并在修复资料或解析问题后重新构建。候选结果不会自动替换已发布知识。

## 草稿审核、质量和来源

草稿页面顶部会显示“未发布草稿”审核栏。审核时建议依次检查：

1. 目录与正文是否覆盖本次想沉淀的模块。
2. 每个关键结论的来源路径和行号是否准确。
3. “知识质量”中的问题、修复建议和代码元数据是否需要处理。
4. 图谱与前端地图是否在当前版本可用，并且关系符合预期。

确认后选择“发布版本”。如果不发布，当前正式知识保持原样；可随时返回知识生产继续处理。

## 图谱与前端地图

- **图谱**：展示代码实体及其关联，适合从模块、符号或引用关系理解项目。可通过筛选、搜索和点击节点收窄范围；知识较多时优先聚焦一个目录或实体，避免把全部节点压缩成难以阅读的视图。
- **前端地图**：面向前端项目展示路由、页面、组件和设计系统线索。它只对管理员开放，并以可用的前端候选包为前提。

若两者暂无内容，先确认当前资料已成功构建并已生成对应候选结果；不要通过重复上传来“刷新”图谱。

## 权限

| 角色 | 主要能力 |
| --- | --- |
| 工作区管理员 | 管理项目、成员、系统设置、发布、模型配置和项目级正式化设置 |
| 项目管理员 | 维护本项目资料、构建、草稿与发布，并管理项目接入 |
| 项目成员 | 在已获授权项目中接入资料、发起构建和处理反馈；不能绕过发布边界 |
| 只读成员 | 阅读项目资料、已发布知识和来源；不能触发生产操作 |

实际按钮会按工作区与项目权限显示。没有操作权限时，可以阅读状态和原因，但不能执行写入或发布。

## 接入 Codex / MCP

在“项目设置 → Codex 接入”创建项目专用 Token，并复制页面生成的 `.codex/config.toml` 和 `AGENTS.md` 片段。Token 明文只显示一次；遗失后请撤销并新建。

MCP 只读取当前已发布版本，包含搜索、架构、模块、符号、变更上下文、源代码、版本读取和反馈上报工具。返回结果带路径、行号、版本标识和内容哈希引用，方便回到知识资料核验。

## 常见情况

| 现象 | 含义与处理 |
| --- | --- |
| 上传暂时中断 | 已验证文件会暂存；安全重试或刷新后重新选择同一文件夹继续。已发布知识不会变化。 |
| 构建详情显示失败 | 查看失败阶段与详细错误，修复后发起新的重试。失败证据会保留。 |
| 草稿看起来正常但搜索没有变化 | 草稿尚未发布；发布版本后才会进入正式读取路径。 |
| 图谱 / 前端地图没有内容 | 检查构建与候选包状态，不要重复上传同一资料。 |
| LLM 没有生效 | 查看构建 warning；基础生成仍可产生可审核知识。 |
| MCP 返回未发布或无权限 | 确认项目已有已发布版本、Token 属于该项目且未被撤销。 |

所有核心流程的错误提示均会显示操作名称、服务端错误码、可读原因、数据安全说明和下一步；遇到 500 或网络错误时，请先打开对应错误详情与构建阶段，再决定重试。

## 当前生产基线

截至 2026-08-04，正式环境的知识内核、前端知识和资料存储均已启用 active 模式，两个现有项目的前端覆盖也已提升为 active。该状态不改变“人工审核、人工发布”的边界；新上传和新构建永远不会自动替换正式知识。
