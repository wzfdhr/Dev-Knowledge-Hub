# 资料上传页紧凑管理台设计

## 背景

当前资料上传页已经具备文件夹扫描、本地安全过滤、断点续传、服务端校验、内容版本创建、来源替换和导入历史等完整能力，但首屏存在以下体验问题：

- 上传区与进度区尺寸过大，空闲状态仍占据大量空间。
- 大面积网格背景和分散说明削弱了主操作与信息层级。
- Git HTTPS、服务器路径被隐藏在“更换资料来源”弹窗中，管理员需要额外跳转才能维护来源。
- 导入历史位于首屏下方，无法快速判断当前来源和最近导入结果。
- 安全边界、容量限制和发布语义混在正文中，不利于快速扫描。

本设计将页面调整为用户确认的“紧凑管理台”方向，在不改变后端接口和上传语义的前提下，重新组织来源、上传、进度和历史信息。

## 目标

1. 将项目文件夹、Git HTTPS、服务器路径三种来源放在同一工作区内配置。
2. 让当前来源、主要动作和最近导入结果在首屏可见。
3. 让进度信息按需出现，避免空闲状态长期占据大面积空间。
4. 保留本地过滤、断点续传、服务端二次校验、人工发布等安全语义。
5. 覆盖桌面、平板和移动端，不引入文字溢出、控件重排抖动或不可操作状态。

## 非目标

- 不修改上传会话、分页传输、重试、去重和内容版本后端协议。
- 不改变来源替换、归档和正式知识发布规则。
- 不新增拖放上传、ZIP 导入、自动发布或批量删除历史记录。
- 不重构项目级导航和其他控制台页面。

## 页面结构

### 1. 紧凑页头

页头保留“项目资料 / 资料上传”标题与一句简短说明，不再重复解释完整过滤流程。右侧仅保留来源状态或必要的来源管理命令，避免同时出现多个同义入口。

### 2. 页内来源切换

使用 Ant Design `Segmented` 作为一级模式切换：

- 项目文件夹
- Git HTTPS
- 服务器路径

切换分段控件只改变当前配置视图，不立即修改项目资料来源。用户完成选择或填写后，仍需点击明确的提交按钮。当前已连接来源在分段控件右侧显示状态，不使用仅靠颜色表达的状态。

### 3. 来源配置区

#### 项目文件夹

使用紧凑横向区域，包含文件夹图标、标题、单句安全说明和“选择项目文件夹”主按钮。隐藏的原生目录输入继续作为浏览器不支持 `showDirectoryPicker` 时的回退。

#### Git HTTPS

在页面内显示 HTTPS URL、可选个人访问 Token 和“连接 Git 仓库”按钮。Token 输入继续使用密码类型，不回显已保存凭据。

#### 服务器路径

在页面内显示服务器绝对路径和“连接服务器目录”按钮，并明确说明该路径必须由服务器自身可读。

如果当前项目已有其他来源，提交后继续调用既有替换接口；旧来源和正式知识保留为只读历史。

### 4. 安全摘要条

文件夹模式下在配置区下方展示四项短信息：

- 本机预过滤：敏感内容不离开电脑。
- 50,000 个源码文件上限。
- 2 GiB 可采集源码上限。
- 上传不会自动改变正式知识。

这些信息使用等宽信息格，不使用装饰性卡片或大段说明。移动端调整为两列。

### 5. 动态进度区

空闲时不渲染完整阶段列表。开始扫描、过滤或上传后，在来源配置区下方出现紧凑进度区，包含：

- 当前阶段名称。
- 百分比进度条。
- 已处理文件和字节数。
- 速率与预计剩余时间（有数据时）。

阶段明细保留五个既有阶段，但在紧凑区域中以短标签展示。失败时进度区切换为错误状态并就近显示安全重试说明；完成后显示内容版本结果。

### 6. 本地预检与确认

扫描完成后在进度区下方展开过滤报告和确认操作。报告继续展示扫描文件、源码上传、资源登记、自动忽略、上传大小以及忽略原因。确认操作明确说明上传不会自动发布，并保持“确认并开始上传”为唯一提交入口。

### 7. 最近导入

导入历史作为首屏主要区域，使用紧凑表格展示：

- 来源类型。
- 开始时间。
- 采集文件数与文本大小。
- 服务端过滤数量。
- 状态。
- 失败代码（存在时）。

空状态保留简短说明。移动端允许表格横向滚动，表格设置稳定最小宽度，避免列内容相互覆盖。

## 组件边界

### `ProjectImportsPage`

负责来源查询、来源模式、目录选择、连接与替换 mutation、报告/结果组合和历史查询。页面不新增后端状态，也不复制上传协议逻辑。

### `ImportSourceSwitcher`

新增受控展示组件，负责分段控件、当前来源摘要和三种来源配置表单。通过回调触发目录选择或连接操作，不直接访问 API。

### `ImportProgress`

保留现有格式化和阶段映射逻辑，调整为空闲紧凑提示、运行中横向进度、失败和完成状态。组件继续只依赖 `ImportProgressValue`。

### `FolderFilterReport` 与 `ImportResultReport`

保留数据契约和语义，仅调整布局与视觉层级。

### 导入历史

从页面内联 JSX 提取为 `ImportHistory` 展示组件，接收查询状态、报告列表和重试回调，降低页面主体复杂度。

## 数据流

1. 页面读取当前 repository 和最近 import reports。
2. 用户切换来源模式，仅更新本地 `sourceKind`。
3. 文件夹模式选择目录后，浏览器在本机扫描并持续更新 `progress`。
4. 本地扫描完成后生成 `FolderImportReport`，页面展示过滤结果并等待确认。
5. 用户确认后复用或创建 upload repository，再调用既有分段上传接口。
6. Git 或服务器路径提交后，根据是否存在 repository 调用 connect 或 replace 接口。
7. 成功后失效 repository、build、release 和 import history 查询，UI 重新读取服务端事实。
8. 任何来源连接或上传都不会自动构建、发布或替换正式知识。

## 错误与恢复

- Repository 查询失败：显示页面级错误和只读重试。
- 来源连接失败：错误显示在当前来源配置区内，不关闭或重置用户输入。
- 本地目录读取失败：进度区显示失败详情，允许重新选择目录。
- 临时上传失败：保留约 24 小时的已验证文件，并提供安全重试。
- 上传会话失效：要求重新选择同一项目文件夹，不宣称内容版本已创建。
- 历史查询失败：只影响历史区域，不阻塞来源配置和上传。
- 所有错误说明继续明确“当前已发布知识未改变”。

## 可访问性

- 来源分段控件保留可读标签和键盘操作。
- 所有输入都有持久可见的标签；Token 使用合适的自动完成设置。
- 进度变化通过 `aria-live="polite"` 发布，失败信息使用 `role="alert"`。
- 状态同时使用文字和颜色，不依赖颜色单独表达。
- 焦点样式与现有控制台保持一致。
- 表格保留语义化表头；移动端滚动容器可键盘聚焦时需要可见焦点。

## 响应式设计

- 大于 1000px：来源切换和状态同排，文件夹入口横向布局，历史使用完整列。
- 761px 至 1000px：缩短辅助文字，主按钮保持稳定宽度。
- 小于等于 760px：来源分段控件三等分；文件夹入口变为两行，主按钮占满；安全摘要两列；进度元数据换行；历史横向滚动。
- 320px 最小宽度下不得出现页面级横向滚动、按钮文字截断或控件重叠。

## 测试策略

### 组件测试

- 三种来源模式均可在页面内切换。
- 切换来源不调用 API，提交时才调用 connect 或 replace。
- 已连接来源正确显示，替换说明保持可见。
- 空闲、运行、失败、完成进度状态内容正确。
- 本地过滤报告仍需确认后才上传。
- 上传恢复、会话失效和成功结果沿用现有回归测试。
- 历史加载、失败、空状态和数据表格均有覆盖。

### 视觉与响应式验证

- 使用 Playwright 在桌面、平板和移动端截图。
- 检查 320px、390px、768px、1280px 视口下的溢出与重叠。
- 验证来源切换、表单填写、目录选择回退和历史横向滚动。
- 对比空闲、上传中和失败状态，确认动态区域不会导致不可理解的布局跳变。

## 验收标准

1. 三种来源可直接在资料上传页内切换和配置，无需打开来源弹窗。
2. 当前来源、主操作和最近导入在桌面首屏可见。
3. 空闲状态不展示大面积空进度面板，运行状态仍能看到完整进度信息。
4. 现有上传过滤、恢复、替换和人工发布语义不发生变化。
5. 所有既有资料上传测试通过，并新增来源切换和历史组件测试。
6. 类型检查、相关 Vitest、构建和 Playwright 响应式检查通过。
7. 320px 至宽屏范围内无文字溢出、页面级横向滚动或交互控件重叠。
