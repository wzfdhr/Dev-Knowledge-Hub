# 核心流程错误指引设计

## 目标

让资料接入、知识构建、版本发布和图谱加载的接口失败均以中文、可行动且可追踪的方式呈现；用户不需要理解 HTTP 状态、服务端堆栈或浏览器控制台。

## 范围

- 覆盖资料接入（包含上传会话）、构建、创建/发布版本、知识图谱与 React 前端地图。
- 保留现有服务端错误码、权限与数据安全语义；不新增数据库表或持久化用户错误历史。
- 不显示数据库字段名、堆栈、令牌、路径或其他内部实现细节。

## 错误模型

前端新增一个纯函数错误字典，将 `ApiError`（HTTP 状态、`code`、服务端 `message`）与网络异常映射为统一描述：

- `title`：一句明确的中文结论。
- `summary`：发生了什么。
- `safety`：当前资料、候选构建或已发布知识是否受到影响。
- `nextStep`：用户可执行的下一步。
- `retryable`：是否显示“安全重试”。
- `operation`：资料接入、构建、发布、图谱之一。
- `diagnosticId`：优先使用服务端错误码；未知错误使用 HTTP 状态与错误码组合。仅用于复制给支持人员。

已知上传错误至少涵盖：网络中断、限流、会话过期/无效、清单不匹配、重复操作、文件限制、权限不足和未知提交失败。构建、发布、图谱继续复用已有明确错误码，例如 `PIPELINE_STAGE_FAILED`、`FRONTEND_PREVIEW_INVALID`、`FORBIDDEN`。未知 `5xx` 统一说明为“服务端未完成操作”，且默认不承诺重试一定安全，除非当前操作已有幂等语义。

## 呈现与交互

### 自动提示

核心流程 mutation 失败后，页面弹出一个可关闭 Modal：

- 标题、状态图标、发生了什么、数据安全、下一步和诊断编号。
- 支持复制诊断编号。
- 仅当 `retryable` 且当前页面拥有原始操作回调时显示“安全重试”；否则显示“我知道了”。
- 弹窗初始焦点放在标题/关闭控件，关闭后焦点回到触发操作，符合现有无障碍规则。

### 页内错误列表

核心流程页面在当前任务区域保留最近一次错误卡，不会因为关闭弹窗而消失：

- 以“需要处理”标题、操作标签、时间、状态和一行摘要组成列表项。
- 展开后显示“发生了什么 / 数据安全 / 下一步 / 诊断编号”。
- 上传页面优先显示最近一次上传失败，并复用已有 `ImportProgress` 的失败状态；构建、发布、图谱页面显示各自当前 mutation/query 的失败。
- 新一次成功操作会清除对应的临时错误卡；服务端导入/构建历史仍是事实来源。

## 组件边界

- `src/client/errors/core-flow-error.ts`：错误分类与中文描述，不依赖 React。
- `src/client/components/core-flow-error-dialog.tsx`：Modal 和页内错误卡；接收描述、关闭与可选重试回调。
- `src/client/pages/project-imports-page.tsx`：上传失败自动显示弹窗与错误卡，替换单一 `ErrorState` 文案。
- `src/client/pages/project-versions-page.tsx`：构建、草稿和发布 mutation 使用同一组件。
- `src/client/pages/project-graph-page.tsx`、`src/client/pages/project-frontend-map-page.tsx`：图谱及前端地图失败使用同一组件。

## 测试与验收

- 单元测试覆盖每种操作的已知错误、未知 `5xx` 与网络错误，断言不会泄漏服务端内部错误文本。
- 组件测试验证上传提交失败会同时显示页内卡片与自动弹窗；安全重试调用原操作；关闭弹窗不删除页内详情；复制诊断编号可用。
- 页面测试验证构建、发布和图谱错误使用对应的中文下一步说明。
- 在键盘下验证打开、关闭和重试的焦点流；移动端弹窗不会产生页面横向溢出。

## 决策

第一期只覆盖用户实际操作频率最高的四类核心流程。全站查询型页面继续使用现有 `ErrorState`，待错误字典稳定后再扩展，避免把全部异常处理一次性改动而降低发布可靠性。
